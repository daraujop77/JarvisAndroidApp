## What changed on Android

- Paid image requests: cloud Scene Builder generation now goes through the durable intent journal (A4); a saved intent whose ID the server never saw is voided and released (B2); pending-storage candidates and any typed pre-dispatch rejection release the scope (B3); unresolved intents are listed, recovered or explicitly released through a banner (B4a, B4b); release compares the expected request ID (B4); the recovery scan skips requests still in flight (B4c).
- Exact bytes: Scene Builder candidates keep the server bytes verified by SHA (C1); Image Studio versions persist outside the composition (B5).
- Streams: a Chat Global error frame recovers by GET before any retry is offered and is not retryable unless the backend sends `retry_safe: true` (A5); an interrupted turn is polled while the server reports it active, through network faults, for up to 10 minutes (D2); Copilot confirmation waits 8 minutes and follows the real task state after a failure (D3); agent streams fail after 45 s of silence into the existing recovery (D4); a Copilot stream cut before any event now reads `request-status` by ID.
- Approvals: candidates, scene confirmations and Location hashes need a decoded preview (E1a, E1c); Reference Pack and batch approvals ask for confirmation (E1b, E1c); Image Studio no longer prefills the Wiki character.
- Chat Global shows every generated image in a message instead of only the first.

## Open items

- Shared full-screen image viewer, Copilot failed-turn state, Reference Pack thumbnails.
- `acknowledgePaidVisual` does not compare the attempt ID; the scan does not validate receipt route and project; a recovered global edit can leave an orphan version.
- D2 and D4 have no automated tests and need a device pass.
- The recovery poll's blocking GET is not tied to the stream's cancel control, so Stop can wait up to its 30 s call timeout.
- The in-flight guard is released when the POST returns, before the caller saves and acknowledges, so a scan can briefly see a completed attempt.
- The Copilot status read after a failed confirmation has no timeout, and Confirm stays enabled if that read fails (a second confirm is idempotent by action hash on the backend).
- Batch approval of Character Studio views approves every CANDIDATE item behind a confirmation dialog, without a per-view decoded-preview gate.
- `app/schemas/com.jarvis.android.data.local.JarvisDatabase/4.json` is generated by the build and is not versioned.
